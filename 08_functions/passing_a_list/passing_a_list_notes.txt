=====================================================================================================================================================
                                                                 PASSING A LIST
=====================================================================================================================================================

CHAPTER OVERVIEW
-----------------------------------------------------------------------------------------------------------------------------------------------------
Passing lists to functions allows programs to handle collections of data efficiently. Instead of repeating loop logic throughout a codebase, 
functions can receive a reference to a list, iterate through its elements, mutate its contents in place, or work safely with an isolated copy.


1. PASSING A LIST TO A FUNCTION
-----------------------------------------------------------------------------------------------------------------------------------------------------
When you pass a list as an argument to a function, the function receives direct access to the contents of that list.

* Concept:
  - The parameter variable binds to the exact memory reference of the passed list object.
  - The function can iterate over elements without returning a new list.

* Code Example (greet_users.py):
>>>  def greet_users(names):
>>>      """Print a simple greeting to each user in the list."""
>>>      for name in names:
>>>          msg = "Hello, " + name.title() + "!"
>>>          print(msg)

>>>  usernames = ['hannah', 'ty', 'margot']
>>>  greet_users(usernames)

* Output:
  Hello, Hannah!
  Hello, Ty!
  Hello, Margot!

* Execution Breakdown:
  - Step 1: `usernames` list is initialized with three string items.
  - Step 2: `greet_users(usernames)` passes the reference of `usernames` to parameter `names`.
  - Step 3: `for` loop iterates over `names`, formatting each element with `.title()` and printing.


2. MODIFYING A LIST IN A FUNCTION
-----------------------------------------------------------------------------------------------------------------------------------------------------
Any changes made to a list inside a function body (e.g., using `.pop()`, `.append()`, or index mutation) permanently alter the original list.

* Problem Context: 3D Printing Workflow
  - Track models waiting to be printed in `unprinted_designs`.
  - Move completed prints into `completed_models`.

* Approach A: Sequential / Procedural (Without Functions):
>>>  unprinted_designs = ['iphone case', 'robot pendant', 'dodecahedron']
>>>  completed_models = []

>>>  while unprinted_designs:
>>>      current_design = unprinted_designs.pop()
>>>      print("Printing model: " + current_design)
>>>      completed_models.append(current_design)

>>>  print("\nThe following models have been printed:")
>>>  for completed_model in completed_models:
>>>      print(completed_model)

* Approach B: Refactored with Specialized Functions (printing_models.py):
>>>  def print_models(unprinted_designs, completed_models):
>>>      """
>>>      Simulate printing each design, until none are left.
>>>      Move each design to completed_models after printing.
>>>      """
>>>      while unprinted_designs:
>>>          current_design = unprinted_designs.pop()
>>>          print("Printing model: " + current_design)
>>>          completed_models.append(current_design)

>>>  def show_completed_models(completed_models):
>>>      """Show all the models that were printed."""
>>>      print("\nThe following models have been printed:")
>>>      for completed_model in completed_models:
>>>          print(completed_model)

>>>  unprinted_designs = ['iphone case', 'robot pendant', 'dodecahedron']
>>>  completed_models = []

>>>  print_models(unprinted_designs, completed_models)
>>>  show_completed_models(completed_models)

* Single Responsibility Principle (SRP):
  - Every function should perform ONE specific job.
  - `print_models()` handles queue processing and state mutation.
  - `show_completed_models()` handles summary display and output formatting.


3. PREVENTING A FUNCTION FROM MODIFYING A LIST
-----------------------------------------------------------------------------------------------------------------------------------------------------
When you want a function to process list elements without destroying or altering the original list, pass a shallow copy using slice notation `[:]`.

* Syntax:
  function_name(list_name[:])

* Mechanism:
  - `list_name[:]` creates a duplicate slice of the full list.
  - Mutations inside the function affect only the duplicate list.
  - The original list remains intact in the caller scope.

* Code Example:
>>>  unprinted_designs = ['iphone case', 'robot pendant', 'dodecahedron']
>>>  completed_models = []

>>>  # Pass a copy of unprinted_designs:
>>>  print_models(unprinted_designs[:], completed_models)
>>>  show_completed_models(completed_models)

>>>  # Original list remains fully populated:
>>>  print("\nOriginal unprinted_designs:", unprinted_designs)

* Performance & Memory Trade-off:
  - Copying large lists consumes extra memory and computation time (O(N) operation).
  - Always pass original lists unless preserving original data is explicitly required.


4. PYTHON MEMORY MODEL (PASS-BY-OBJECT-REFERENCE)
-----------------------------------------------------------------------------------------------------------------------------------------------------
* How Python Handles Arguments:
  - Arguments are passed by object reference (Pass-by-Assignment).
  - Mutating a mutable object (`list.pop()`, `list[0] = val`) modifies the shared object.
  - Reassigning the parameter variable (`list_param = []`) breaks reference to caller object.


5. COMMON MISTAKES AND ERRORS
-----------------------------------------------------------------------------------------------------------------------------------------------------
1. Modifying a List During `for` Loop Iteration:
   - Modifying a list while iterating over it via `for` causes skipped items due to index shifting.
   - Solution: Use a `while` loop with `.pop()`, or loop over a copy `for item in list_name[:]:`.

2. Accidental Data Erasure:
   - Forgetting slice notation `[:]` when calling destructive functions empties original lists.

3. Type Overhead Bug:
   - Passing a single string instead of a list causes character-by-character iteration.
